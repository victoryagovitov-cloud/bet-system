# Улучшения надежности системы

## Проблемы, которые были решены

### 1. Планировщик может зависать
**Решение:**
- Добавлен таймаут для выполнения анализа (10 минут)
- Использование threading для контроля времени выполнения
- Автоматическое логирование таймаутов

### 2. Нет мониторинга
**Решение:**
- Создан `system_monitor.py` для health checks
- Проверка статуса планировщика
- Проверка последней активности
- Проверка доступности API (Scores24, Telegram)
- Проверка свободного места на диске
- Автоматические алерты в Telegram при критических проблемах

### 3. Нет автоматического перезапуска
**Решение:**
- Создан `watchdog_service.py` для автоматического перезапуска
- Проверка каждую минуту
- Максимум 3 попытки перезапуска с cooldown 5 минут
- Логирование всех действий

### 4. Ошибки могут быть тихими
**Решение:**
- Улучшено логирование всех ошибок
- Отслеживание последовательных ошибок
- Критические алерты при превышении лимита ошибок
- Graceful shutdown при получении сигналов

### 5. Нет механизмов восстановления
**Решение:**
- Watchdog автоматически перезапускает планировщик
- Cooldown между перезапусками предотвращает бесконечные циклы
- Сохранение состояния для восстановления

## Новые компоненты

### `system_monitor.py`
Система мониторинга и health checks:
```bash
python system_monitor.py
```

**Проверки:**
- Статус планировщика (запущен/не запущен)
- Последняя активность (не более часа назад)
- Доступность API (Scores24, Telegram)
- Свободное место на диске

**Алерты:**
- Критические проблемы отправляются в Telegram
- Cooldown 5 минут между алертами одного типа
- Статус сохраняется в `.system_status.json`

### `watchdog_service.py`
Автоматический перезапуск планировщика:
```bash
python watchdog_service.py
```

**Функции:**
- Проверка каждую минуту
- Автоматический перезапуск при падении
- Максимум 3 попытки с cooldown 5 минут
- Логирование в `logs/watchdog.log`

### Улучшенный `auto_cycle_scheduler.py`
**Новые возможности:**
- Таймаут 10 минут на выполнение анализа
- Отслеживание последовательных ошибок (максимум 5)
- Graceful shutdown при SIGINT/SIGTERM
- Улучшенное логирование с временем выполнения

## Установка и запуск

### 1. Установка зависимостей
```bash
pip install psutil  # Для проверки процессов (опционально)
```

### 2. Запуск системы

**Вариант 1: Только планировщик (базовый)**
```bash
python auto_cycle_scheduler.py
```

**Вариант 2: С watchdog (рекомендуется)**
```bash
# Терминал 1: Watchdog
python watchdog_service.py

# Терминал 2: Планировщик (watchdog его запустит автоматически)
python auto_cycle_scheduler.py
```

**Вариант 3: Полный мониторинг**
```bash
# Терминал 1: Watchdog
python watchdog_service.py

# Терминал 2: Планировщик
python auto_cycle_scheduler.py

# Терминал 3: Мониторинг (запускать периодически или через cron)
python system_monitor.py
```

### 3. Автозапуск при старте системы (Windows)

Создайте `start_system.bat`:
```batch
@echo off
start "Watchdog" python watchdog_service.py
timeout /t 3
start "Scheduler" python auto_cycle_scheduler.py
```

Добавьте в автозагрузку Windows или используйте Task Scheduler.

## Мониторинг

### Логи
- `logs/auto_cycle.log` - логи планировщика
- `logs/watchdog.log` - логи watchdog
- `logs/health_check.log` - логи мониторинга

### Статус
- `.system_status.json` - текущий статус системы
- `.auto_cycle.lock` - lock файл планировщика
- `.watchdog.lock` - lock файл watchdog

### Проверка статуса
```bash
python system_monitor.py
```

Или проверьте `.system_status.json`:

## Настройка

### Таймауты
В `auto_cycle_scheduler.py`:
```python
CYCLE_TIMEOUT = 600  # 10 минут (можно изменить)
MAX_CONSECUTIVE_ERRORS = 5  # Максимум последовательных ошибок
```

### Watchdog
В `watchdog_service.py`:
```python
MAX_RESTART_ATTEMPTS = 3  # Максимум попыток перезапуска
RESTART_COOLDOWN = 300  # 5 минут между перезапусками
```

### Мониторинг
В `system_monitor.py`:
```python
ALERT_COOLDOWN = 300  # 5 минут между алертами
ALERT_CHAT_ID = "@TrueLiveBet"  # Канал для алертов
```
